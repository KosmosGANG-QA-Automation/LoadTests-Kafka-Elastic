# Нагрузочное тестирование с NBocker, Kafka и Elasticsearch

[![Run Load Tests](https://github.com/KosmosGANG-QA-Automation/LoadTests-Kafka-Elastic/actions/workflows/load-tests.yml/badge.svg)](https://github.com/KosmosGANG-QA-Automation/LoadTests-Kafka-Elastic/actions/workflows/load-tests.yml)

## Архитектура проекта

Данный проект представляет собой полноценную систему нагрузочного тестирования, которая демонстрирует комплексные навыки AQA инженера в следующих областях:

### 1. Нагрузочное тестирование
- Использование **NBomber** как наиболее нативного инструмента для .NET экосистемы
- Сценарии тестирования: линейный рост пользователей, пиковая нагрузка
- Анализ производительности API под различными условиями

### 2. Контейнеризация
- **Docker Compose** для локального развертывания полной инфраструктуры
- **Kubernetes** манифесты для деплоя в продакшн-клистере
- Микросервисная архитектура с изолированными сервисами

### 3. Наблюдаемость (Observability)
- **Elasticsearch** — сбор и индексация логов
- **Kibana** — визуализация данных и построение дашбордов
- **Kafka** — надежный транспорт для структурированных логов
- **Serilog** — структурированное ведение логов в .NET

## Инструкция по локальному запуску через Docker Compose

### Шаг 1: Подготовка
Убедитесь, что установлены:
- Docker Desktop
- .NET 8 SDK (для возможной модификации кода)

### Шаг 2: Запуск инфраструктуры
Перейдите в директорию с проектом и выполните:

```bash
docker-compose up -d
```

Это запустит следующие сервисы:
- **target-api** - API на порту 5000 (внутри контейнера 8080)
- **kafka** - Брокер сообщений в режиме KRaft на порту 9092
- **elasticsearch** - Поисковый движок на порту 9200
- **kibana** - Веб-интерфейс визуализации на порту 5601

### Шаг 3: Проверка доступности сервисов

1. **API сервис**: `http://localhost:5000/api/orders/{id}`
   - Возвращает статус создания заказа

2. **Kafka**: `localhost:9092` — доступен для продюсеров

3. **Elasticsearch**: `http://localhost:9200`
   - Проверка: `curl localhost:9200/_cluster/health`

4. **Kibana**: `http://localhost:5601`
   - Откройте в браузере и следуйте инструкциям по подключению к Elasticsearch

### Шаг 4: Запуск нагрузочных тестов

```bash
# Перейдите в папку с тестами
cd src/LoadTests

# Соберете проект
dotnet build

# Запустите тесты
dotnet run
```

Во время выполнения тестов NBomber будет:
- Симулировать линейный рост пользователей
- Вызвать пиковую нагрузку
- Показывать метрики успеха/ошибок
- Логировать каждый запрос в Kafka

### Шаг 5: Анализ логов в Kibana

1. Откните Kibana по адресу `http://localhost:5601`
2. Перейдите во вкладку "Discover"
3. Выберите индекс `logs-*` (автоматически создается Serilog.Kafka)
4. Фильтруйте по:
   - `status:success` / `status:error`
   - Временным диапазонам
   - Источникам запросов

5. Постройте дашборд, показывающий:
   - Количество успешных заказов в минуту
   - Процент ошибок при пиковой нагрузке
   - Среднюю задержку обработки

## Как этот проект доказывает компетенции AQA инженера

1. **Навыки автоматизации тестирования**: Вы не просто пишете тесты, вы создаете полноценную систему нагрузочного тестирования с автоматизированной инфраструктурой.

2. **Понимание архитектуры микросервисов**: Разделение ответственности между Target API, Kafka, Elasticsearch демонстрирует понимание того, как современные системы общаются между собой.

3. **Работа с реальными инструментами**: Использование NBomber, Kafka, Elasticsearch — это industry-standard инструменты, с которыми AQA инженеру предстоит столкнуться на работе.

4. **Навыки DevOps**: Docker Compose и Kubernetes манифесты показывают способность работать с современной инфраструктурой развертывания.

5. **Навыки мониторинга и observability**: Настройка сбора логов через Serilog → Kafka → Elasticsearch — это критически важный навык для обеспечения стабильности продакшн-систем.

6. **Анализ результатов**: Возможность проанализировать производительность системы под нагрузкой и выявить Bottlenecks через Kibana дашборды показывает аналитический ум.

7. **Документирование**: Подробный README с архитектурой и инструкциями показывает профессиональный подход к документированию проекта, что критически важно для AQA позиций.

8. **Интеграция всего стека**: Умение объединить разные технологии в работающую систему — ключевая Soft Skill для AQA роли, требующая взаимодействия с разработчиками, DevOps и стейкхолдерами.
